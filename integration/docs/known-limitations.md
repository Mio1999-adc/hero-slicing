# Known limitations

- The stock FlexRIC KPM monitor completes the two-gNB live run. Its E42 event loop aborted in the attempted three-node concurrent-subscription run, so three-node reporting is not claimed. Three-gNB native traffic and independent E2 Setup were observed.
- The integration advertises only KPM v3 periodic reporting for cell-scoped DL/UL PDCP SDU throughput with `noLabel`. It does not advertise every metric collected in CSV, per-UE KPM records, handover identity behavior, or arbitrary labels/styles.
- There is no automatic SCTP reconnection or resubscription. A failed or lost gNB association is terminal for that agent; restart the native simulation to recover it.
- Scheduler control is a private local RC extension using generic FlexRIC RC v1.03 codecs. It is not standardized or interoperable with stock standard RC scheduler actions. Only BWP 0 `MaxDlMcs` (0..30) has been validated. FlexRIC's E2AP ACK is not itself an application-level success signal; inspect the service-model outcome and native trace.
- The control pump polls an owned per-agent queue on the ns-3 simulation thread. A short bounded protocol callback wait remains part of this private implementation; it cancels the queued operation on timeout. It is not a hard-real-time slot-boundary API.
- The measurement demo uses constant-position clusters and the installed EPC/radio configuration. It preserves native LENA attachment/scheduler behavior but does not test mobility or handover across the E2 identity contexts.
- Integration overhead numbers are one local run with RSS/CPU sampling at approximately 100 ms. Short peaks can be missed and the numbers are not capacity guarantees.
- ns-3, LENA, and FlexRIC are imported from the existing source/build trees. The build instructions do not provision system packages or rebuild source trees from a clean machine; they reproduce the integration against the documented installed revisions.
- Slice assignment, `SliceBudgetManager`, and the opt-in PF-derived per-slice upper-cap scheduler are implemented. The baseline scheduler remains the default. Live local and regional PPO now consumes native measurement windows and updates the per-gNB manager on the simulator event thread; this is verified for one-gNB local and two-gNB regional radio-only runs. It does not add an E2 slice-ratio action.
- Live PPO uses synchronous Python sidecar IPC from the simulation event callback. Policy inference/training pauses ns-3 event processing and can make real-time E2 sessions lag; radio-only unpaced training is the validated path. Regional control waits for aligned samples, and the selected local or regional tier is exclusive.
- PPO reward weights, normalization scales and regional mean aggregation are experimental implementation choices. The supplied HERO document does not define final weights or ConvexSolve constraints/objective, residual resource handling, or final regional aggregation. No scientific result or paper-equivalence claim is made from these defaults.
- Application delay and packet-delivery reliability targets can be configured and exported as profile metadata, but the current measurement provider does not collect per-application UDP deadline misses or delivery ratios. Only the configured minimum-throughput diagnostic is compared against delivered DL PDCP SDU throughput. Per-UE traffic/QoS variation within one slice is not yet configurable.
- No DRL, federated learning, or Flower implementation is included.
