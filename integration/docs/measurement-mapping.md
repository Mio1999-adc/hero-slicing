# Phase 03 native measurement definitions

The provider in `integration/kpm/lena-measurement-provider.{h,cc}` observes native LENA traces and publishes interval snapshots. These are local measurements, not E2SM-KPM wire records or verified standard KPM metric mappings. No values are synthesized. A metric with no applicable receiver/source is omitted in the API (`std::nullopt`) and left blank in CSV.

The supported scenario currently requires one BWP per gNB and one BWP per registered UE. This restriction preserves correct BWP attribution because the installed RRC bearer traces do not carry a BWP identifier. Each provider is attached to one gNB and its cell; UE rows are keyed by IMSI, RNTI and an RNTI reuse generation. The cell row is the sum of its UE rows for additive metrics.

## Snapshot and CSV contract

`LenaMeasurementProvider` implements the existing `KpmMeasurementProvider::LatestSnapshot()` interface and also exposes `LatestNativeSnapshot()` for exact integer counters. Each sample carries simulation nanoseconds, sequence, E2 node identity, cell/BWP, and UE context. Trace callbacks and periodic sampling run on the simulator thread. The latest immutable copies are protected by a mutex for reporter-thread reads; the provider never lets a foreign thread traverse ns-3 objects. `SampleNow()` flushes a non-empty partial final window. `Stop()` cancels the event and disconnects attached traces before simulator destruction.

`MeasurementCsvWriter` writes one cell row and one row for each observed UE context per sample. Blank numeric cells mean unavailable; an actual zero is serialized as `0`. CSV counters are interval deltas (not cumulative process counters), except `available_prbs` and the sampled connection state. The example uses a fixed seed, fixed run, constant UE positions, fixed UDP packet counts and sizes, and outputs `sequence,begin_sim_ns,end_sim_ns,...` to the path given by `--csv`.

## Standard KPM mapping status

Phase 04 advertises and reports only two explicitly local KPM measurement names: `HERO.DL.PDCP.SDU.Throughput.Mbps` and `HERO.UL.PDCP.SDU.Throughput.Mbps`. Both are cell-scoped, `noLabel` interval-average rates calculated from the corresponding native PDCP receive SDU-byte delta. DL is measured at UE PDCP receive and summed for the provider's serving cell; UL is measured at gNB PDCP receive. The values are encoded as KPM real measurement records and are not represented as standardized KPM measurement definitions.

Similar standard names such as `DRB.UEThpDl`, `DRB.PdcpSduVolumeDL`, or `RRU.PrbTotDl` require a separate check of the exact E2SM-KPM v3 definition, labels, units, aggregation, granularity and reporting semantics before any standard mapping is proposed. No other local Phase 03 metric is advertised in Phase 04. See [phase04-validation.md](phase04-validation.md) for the live decoded values and limits.

## Slice-associated UE metadata

The opt-in scenario copies `slice_id`, `slice_type`, `application_type`, `qos_profile`, offered payload rate, configured throughput/delay/reliability targets, and packet profile into UE rows in the same local CSV. These fields originate from simulator configuration and UE assignment; they are labels/requirements, not radio observations. The dashboard associates each latest UE record with its serving gNB and compares a configured minimum DL throughput only with the native `dl_delivered_sdu_throughput_mbps` value above. A missing target or missing measurement is never treated as zero performance for status evaluation. Configured delay and reliability are not evaluated because no per-application deadline/delivery measurement is present.

For the local resource-efficiency diagnostic, `dl_rx_pdcp_sdu_bytes * 8 / dl_allocated_prb_symbols` is reported as bits per PRB-symbol for the same interval. The denominator is the existing DCI-derived native PRB-symbol counter. This ratio is not an SLA metric, and it should only be compared under compatible BWP/numerology configurations. The opt-in experimental slice scheduler records its per-invocation RBG-symbol budget separately in its manager; this existing telemetry field is not retroactively redefined as slice budget consumption.
